## What Was Built
- **Syscall `#50..#65` pointer validation (`triton/desktop/guest-200.asm`):** Added a single kernel validation routine `k_check_user_ptr` that reads the calling task's `[UBASE, ULIMIT)` directly from TCB `+36` and `+39` (covering regular tasks and App 4's 20-bank workspace without special-casing) and returns `ERR_BADPTR` (`-14`) on any out-of-range buffer, struct, or unterminated path. Every pointer-taking handler in `k_fs2_syscall_dispatch` (`#50..#60`, `#63..#65`) calls `k_check_user_ptr`, and `drv_fs_read_impl` / `drv_fs_doc_load_impl` validate the actual write length (including `max_trytes <= 0` full-file reads and Unit 0 trailing-NUL writes) before copying any data.
- **Error codes (`triton/desktop/guest-200.asm`):** Defined `.equ` constants for the error codes returned by the path syscalls (`ERR_FS_ERR = -1`, `ERR_FS_NO_UNIT = -4`, `ERR_FS_WP = -5`, `ERR_BADPTR = -14`).
- **Generated documentation (`triton/desktop/gen_desktop_doc.js`):** Added `desktop/gen_desktop_doc.js`, which parses `desktop/guest-200.asm` (`k_fs2_syscall_dispatch`, `.equ ERR_*`, and `k_init_task_slot`) and regenerates `DESKTOP.md` §7, `DESKTOP.md` §8.1, and `desktop/syscall-table.json`.
- **Wall clock & build flag (`triton/desktop/build_desktop2.js`, `triton/desktop/tritos-desktop-2.html`):** Updated browser boot in `tritos-desktop-2.html` to pass `clock: Date.now` to both `TritonWASM.createSync` and `new TritonJS`, while keeping fixed clocks in tests unchanged. Added `--no-ptr-check` (and `--out`) to `build_desktop2.js` for the `p-03` positive control.
- **New test suite (`p-01..p-07`):** Added `p-01-pointer-probes.js`, `p-02-coverage.js`, `p-03-positive-control.js`, `p-04-docs.js`, `p-05-regressions.js`, `p-06-builds.js`, `p-07-real-browser.js`, `p-common.js`, and `p-run-all.js`.

## Guest Changes (One Line Each)
- The path parser zero-fills each component buffer before copying (disclosed from 2.0 base tree).
- In the falling-block game, the hold/swap reorders `SYSCALL #9` and its store (disclosed from 2.0 base tree).
- Added `.equ` error code definitions `ERR_FS_ERR` (`-1`), `ERR_FS_NO_UNIT` (`-4`), `ERR_FS_WP` (`-5`), and `ERR_BADPTR` (`-14`) in `guest-200.asm`.
- Added single kernel routine `k_check_user_ptr` (with `; __NO_PTR_CHECK__` build hook) validating `[ptr, ptr + len - 1]` and NUL-terminated paths against TCB `+36` (`UBASE`) and `+39` (`ULIMIT`).
- Updated `k_fs2_syscall_dispatch` (`kfsd_50..kfsd_65`) to call `k_check_user_ptr` on every pointer argument and set `K_FS_CHECK_USER` (Bank 74 `+1452`) for `#52` and `#64`, moving `.org 65400` to `.org 66000`.
- Updated `drv_fs_read_impl` and `drv_fs_doc_load_impl` to validate the actual write length (including `max_trytes <= 0` and Unit 0 trailing NUL) via `k_check_user_ptr` before copying data and to avoid Unit 0 fallback on `ERR_BADPTR`.
- Fixed `dfui_cnt_lp` in `drv_fs_unit_info_impl` to break out immediately when `fs_slt_get_link` returns `-99` (I/O error on an ejected unit) instead of looping over all remaining sectors.

Screenshot saved at `triton/desktop/p07-clock-screenshot.png` (and `logs/p07-clock-screenshot.png`).
- **Existing test changes:** None of the existing Desktop 2.0 or 1.1.2 test files or harness files (`d20-common.js`, `t3-common.js`, `tritfs-ref.js`) were modified (`harness.diff` contains only the newly added `triton/desktop/tests/p-common.js`).
- **Requirements not met:** None (all `p-01..p-07` and `d20-01..07` tests pass, with `p-07` using the documented `readFbString` fallback).
