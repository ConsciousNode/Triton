# Triton 2.1: symbol-table patch for the in-OS assembler

ConsciousNode SoftWorks. Xinu rules: single file, zero dependencies, offline, no network APIs.
**Inline everything, and label every inline.**

This is a **patch release** of Triton 2.0, a balanced-ternary computer whose OS (TritOS) assembles itself.

An audit found that the **in-OS assembler and the JS assembler disagree on four kinds of source**. In each case the in-OS assembler produces a wrong program silently instead of an error. TritOS's own source triggers none of them, so the self-hosting fixed point still holds.

Fix exactly these four, change nothing else, and prove every fix with tests that **fail on 2.0 and pass on 2.1**.

## Attached

- `triton.html`, `ISA.md`, `REPORT.md`, `tests/run.js`: Triton 2.0 as delivered.
- `AUDIT.md`: the audit and its findings.
- `audit/hash-collision.js`: a reproducer for all four defects.
- `audit/unseen.js`: self-hosting on randomized source edits.
- `audit/isa-bigint.js`: arithmetic checked against a BigInt model of `ISA.md`.

All three audit scripts must keep running unmodified.

## The four defects

1. **Hash-only symbols.** The in-OS assembler stores each label as `h = h·41 + upper(c)` in one 27-trit word and resolves references by comparing hashes alone. `ay` and `b0` both hash to 2754, so `JMP b0` silently assembles to `ay`'s address.
2. **Undefined labels.** In-OS, a reference to an undefined label silently becomes address 0. The JS assembler rejects it.
3. **Duplicate labels.** Both assemblers accept a duplicate definition, but they disagree on which one wins: JS takes the last definition, in-OS the first.
4. **Case.** The JS assembler treats labels case-sensitively; the in-OS assembler upper-cases them. So `Loop:` and `LOOP:` are two labels in JS and one in-OS.

## What to build

- **In-OS symbol table:** store each label's **full name** (for example, in a string pool) and compare full names. A hash may still be used to bucket or speed up lookup, but a hash match alone never resolves a symbol.
- **Errors, in both assemblers:** undefined labels and duplicate labels become errors. Each error reports the line number and the label name; the in-OS assembler prints it in the shell. No output image is written when an error occurs. Document the in-OS behavior in `ISA.md`.
- **One case rule:** labels are case-insensitive in both assemblers, matching what the in-OS assembler already does. State the rule in the `ISA.md` grammar section.
- **Hold the self-hosting budget:**
  - The in-OS assembler reads source from `Disk[500..]`, which caps it at 19,182 characters.
  - TritOS 2.0 is 16,774 characters.
  - Report 2.1's source length and the remaining headroom, generated by script.
  - If the fix doesn't fit, say so plainly and propose the smallest change that makes room. Don't silently trim features or comments to fit.
- **A positive control:** a build-time switch `symbolMode: "hashOnly" | "names"`. `hashOnly` reproduces 2.0's in-OS behavior exactly. The tests below must catch it.

## Forbidden

- Making the in-OS assembler call, consult or embed the JS assembler's output, or any precomputed symbol table.
- Special-casing TritOS's own labels, or any test's labels.
- Changing the ISA, the VMs, or any opcode encoding. This patch is assembler-only.
- Editing TritOS source just to make tests pass, except for the assembler itself.
- Hand-typed numbers in docs. Every figure comes from a script.

## Tests

Add these as `tests/symbols.js`, and run them in both `names` mode and `hashOnly` mode.

1. **Collision corpus.**
   - Generate **every** pair of distinct labels of length ≤ 3, over the identifier alphabet, whose 2.0 hashes are equal.
   - Also generate ≥ 200 pairs of length 6–12 that collide through 27-trit wraparound, found by search. Document the search.
   - Embed each pair in a small program that defines both labels and references each one.
   - Both assemblers must emit identical trytes. `hashOnly` must fail on at least 99% of the pairs.
2. **Undefined and duplicate labels.** Cover undefined labels, duplicates, and case-only duplicates such as `Loop` and `LOOP`. Both assemblers must reject each one, reporting the same line and the same label. `hashOnly` must fail this test.
3. **Differential fuzz.**
   - Generate 2,000 random label-heavy programs: 50–300 labels, mixed case, many short labels, forward and backward references.
   - Both assemblers must agree byte for byte, or both must reject.
   - Seed from a fixed list, and log every seed.
4. **Fixed point.** TritOS 2.1 assembled in-OS must equal the JS-assembled image, and the self-built image must boot to the shell. The test must also report the source length against the 19,182-character cap.
5. **Regressions.** These must all still pass, unmodified:
   - Argon's 8 tests in `tests/run.js`;
   - `audit/unseen.js`;
   - `audit/isa-bigint.js`;
   - `audit/hash-collision.js`, which must now report "agree" on every case.
6. **Static scan.** No network or storage APIs. Every inline is labeled.
